## Symptoms

WS connected at 10:46:02 then ATO auto-paused nifty_ltp_websocket_failed at 10:46:05 before first tick

## Technical impact

on_feed_stale → on_websocket_crash → REST fallback + algo pause cascade

## Trading impact

ATO paused repeatedly with nifty_ltp_feed_stale warnings

## Root cause

Feed stale watchdog only applied 09:15 startup grace, not grace after mid-session WS reconnect when last_update_at is None

## Contributing factors

- consumer_max_age_seconds=5
- WS connect-to-first-tick latency

## Investigation

logs_uat/.../drishti/logs/all.log lines 104602–104605 IST

## Files / modules

- core/nifty_ltp_feed.py
- core/nifty_ltp_websocket_feed.py

## Logs referenced

- logs_uat/runtime/2026-06/2026-06-25/drishti/logs/all.log

## Fix implemented

mark_transport_started() + is_within_transport_grace() — 30s grace after WS connect / REST service start

## Why this fix works

Distinguishes cold reconnect from true feed death

## Regression risk

Very slow first tick (>30s) could still false-positive — monitor ws_ltp audit log
